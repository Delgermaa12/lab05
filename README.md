# Лаборатори №5: API систем тест — Postman ба Newman

**Оюутны нэр:** О.Дэлгэрмаа
**Оюутны код:** B232270024

## Орчин

```text
$ node -v
v20.20.2

$ newman -v
6.2.3
```

Үйлдлийн систем: Debian Linux. 
Тестлэсэн API: `http://localhost:3000`, функц: `POST /registrations`.
Collection нь Postman collection JSON хэлбэртэй бөгөөд Newman-аар ажиллуулсан.

## 3. Newman-ийн үр дүн

| Ажиллуулалт | Файл | assertions executed | assertions failed | exit code |
|---|---|---:|---:|---:|
| PASS | `results/newman-pass.txt` | 27 | 0 | 0 |
| FAIL | `results/newman-fail.txt` | 27 | 1 | 1 |
| DOWN | `results/newman-down.txt` | 27 | 27 | 1 |

Collection доторх тестийн (assertion-ы) тоо: **27** (`results/newman-pass.txt`-ийн assertions executed).

- **PASS:** 12 тестийн бүх assertion тэнцсэн, exit code 0.
- **FAIL:** `lab05-collection-fail.json`-д T01-ийн статусын oracle-ийг зориуд 201-ийн оронд 200 болгосон. Сервер 201 буцаасан тул 1 assertion унаж, exit code 1 болсон. Энэ нь CI quality gate-ийн зарчим: нэг oracle алдаатай бол бүх ажиллуулалт амжилтгүй гэж тооцогдоно.
- **DOWN:** Сервер унтарсан үед `ECONNREFUSED` алдаа гарч, 27 хүсэлт бүгд амжилтгүй болсон, exit code 1.

FAIL ба DOWN-ийн ялгаа: FAIL нь oracle-ийн алдаа (сервер хариулсан ч хариу нь хүлээлттэй таараагүй), DOWN нь интерфейсийн алдаа (`ECONNREFUSED`, сервертэй холбогдож чадаагүй тул хариу ирээгүй бөгөөд oracle хүртэл хүрээгүй).

## 5. Дүгнэлт

Энэ лабораторид би хичээлд бүртгүүлэх REST API-ийн `POST /registrations` функцийг тест дизайны 5 алхмаар шинжилж, Newman-аар автоматжуулсан. Дизайны алхмуудаас хамгийн их бодол шаардсан нь давхар алдааны гаргалт дээр маш ихийг бодсон бөгөөд даалгаврын зөвөөр сайн гаргахын тулд хэрхэн тест хийхээ бодож түүгээр хэд хэлийг туршиж үзсэн бөгөөд заримдаа үнэхээр юу хийгээд байгаагаа ойлгогүй үе мөн байсан. Боломжгүй хослол таарсан: бүртгэлгүй оюутныг идэвхгүй гэж үзэх боломжгүй, учир нь бичлэггүй оюутанд төлөв гэж байхгүй. Зааварт давхар алдаа зэрэг гарвал аль нь буцахыг заагаагүй тул T07-T09 тестээр үүнийг тогтоосон. Үр дүнд сервер оюутны бүртгэл, оюутны төлөв, хичээлийн бүртгэл, урьдач нөхцөлийн дарааллаар шалгадаг нь батлагдсан. Тестүүд тодорхой согог илрүүлээгүй, 27 assertion бүгд тэнцсэн. Харин зааварт тодорхойгүй зан төлөв ажигласан: нэг оюутныг нэг хичээлд хоёр удаа бүртгэхэд хоёулаа 201 OK буцаж, registrationID нэмэгдсэн, энэ нь давхар бүртгэлийг хориглоогүй байж болзошгүй дутагдал юм. FAIL ажиллуулалтад нэг oracle-ийг зориуд буруу болгоход exit code 1 болсон нь CI quality gate-ийн зарчмыг харуулсан. DOWN ажиллуулалтын `ECONNREFUSED` нь интерфейсийн алдаа бөгөөд oracle-ийн алдаанаас өөр гэдгийг ялгаж ойлгосон. registrationID нь ажиллуулах бүрд хуримтлагддаг тул яг утгыг шалгалгүй зөвхөн тоо мөн эсэхийг шалгаснаар тестийг давтагдах боломжтой болгосон. Тест бүр өөрийн setup-тай, бие даасан байсан тул дарааллаас хамаарахгүй ажилласан.
